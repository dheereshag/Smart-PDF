**AI-Powered Document Analyzer (PDF Q&A System)**

This repository is a full-stack application for extracting text from PDF files and answering user questions about uploaded documents using a simple retrieval-based approach.

**Features**
- **PDF upload & storage**: Upload files via REST API; files are saved to a local `uploads` directory.
- **Text extraction**: PDF text is extracted using Apache PDFBox.
- **Chunking & retrieval**: Extracted text is split into fixed-size chunks and stored in-memory as text segments.
- **Question answering (RAG-style)**: User questions are matched against stored chunks (simple substring search) and the best matching chunk is returned as the answer.

**Architecture**
- **Frontend**: React + Vite single-page app (see [frontend/package.json](frontend/package.json)).
- **Backend**: Spring Boot (Java 21) REST API providing upload, retrieval and simple search endpoints.
- **Storage**: Uploaded files stored on disk (`uploads/`). Metadata persisted via Spring Data JPA and PostgreSQL.

**Quick Start**

Prerequisites
- Java 21
- Maven
- Node.js (v18+ recommended) and npm
- PostgreSQL

Database
1. Create a PostgreSQL database (example):

```sql
CREATE DATABASE pdfapp;
```

2. Update `webapp/src/main/resources/application.properties` with your DB credentials and optional `openai.api.key` if you intend to integrate OpenAI later.

Key properties:
- `spring.datasource.url` (jdbc url)
- `spring.datasource.username`
- `spring.datasource.password`
- `app.storage.path` (default: `uploads`)

Run the backend

```bash
cd webapp
mvn spring-boot:run
```

The backend starts on `http://localhost:8080` by default.

Run the frontend

```bash
cd frontend
npm install
npm run dev
```

The frontend dev server runs (Vite) at `http://localhost:5173` by default.

**API Endpoints**
- `POST /api/upload` — multipart form upload. Field: `file`. Returns JSON `{fileId, fileName}`.
- `GET /api/upload/{id}/text` — retrieve extracted text for an uploaded file.
- `POST /api/chat` — JSON body `{ "question": "..." }`. Returns `{ question, answer, chunksUsed }`.

Example: ask a question

```bash
curl -X POST http://localhost:8080/api/chat \
     -H "Content-Type: application/json" \
     -d '{"question":"What is this document about?"}'
```

**How it works (high level)**
1. User uploads a PDF via `/api/upload`.
2. Backend saves the file (`FileStorageService`) and extracts text (`PdfExtractionService`).
3. Extracted text is split into ~800-character chunks in `EmbeddingService` and stored in-memory as `TextSegment` objects.
4. When a question is received, the backend performs a simple substring match over stored segments and returns the top match as the answer.

**Important notes & limitations**
- The current `EmbeddingService` uses an in-memory list and simple substring matching — this is a lightweight mock of embedding-based retrieval. It is not persistent across restarts and not suitable for large datasets.
- `openai.api.key` is present in `application.properties` as a placeholder; the project currently doesn't perform real OpenAI calls (see `OpenAiConfig` placeholder).
- For production, replace the in-memory index with a proper embeddings store (vector DB) and secure secrets via environment variables or a secrets manager.

**Project layout (high level)**
